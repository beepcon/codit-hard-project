# 인디게임 개발사를 위한 광고 콘텐츠 생성 서비스

코드잇 AI 고급 프로젝트(개인) · 2026-10-15 ~ 2026-11-13 · 권순균

## 📌 프로젝트 개요

게임과 굿즈를 함께 파는 1인 인디게임 개발사가 디자인·마케팅 인력 없이 광고 콘텐츠를 만들도록 돕는 생성형 AI 서비스다. 이용자는 게임을 등록하고(한 줄 소개, 판매 포인트, 레퍼런스 아트, 선택으로 스타일 LoRA), 기능별 화면에서 요청을 넣는다. 모델은 모두 로컬 GPU(RTX 3090 24GB)에서 돈다.

시연용으로 오픈 라이선스 아트와 NovelAI로 만든 아트를 쓴 가상의 게임 3개를 예시로 등록한다.

| 예시 게임 | 그림체 | 데이터 |
|---|---|---|
| 냥기사의 여행 (`nai`) | 2D 애니풍 횡스크롤 | NovelAI로 만든 아트 (`data/raw/nai`) |
| KayKit (`kaykit`) | 3D 로우폴리 판타지 | 렌더 520장 (`data/raw/kaykit`) |
| 0x72 (`x72`) | 16비트 픽셀 던전 | 장면 520장 (`data/raw/pixel_0x72`) |

## 🖥️ 서비스 앱 (`src/app`)

Streamlit 화면 8개와 대기열 워커로 이루어진다.

| 화면 | 하는 일 |
|---|---|
| 게임 등록·목록 | 게임 이름, 한 줄 소개, 판매 포인트, 레퍼런스 아트, 스타일 LoRA, 그림체 설정 등록·수정. 예시 게임 3개(냥기사, KayKit, 0x72)가 처음부터 등록되어 있다 |
| A 홍보 문구 | 스크린샷 → 스토어 소개 2문장 + SNS 1문장, 규칙 검사표, 생성 기록 |
| B 이벤트 배너 | 요청 → 장면·문구 변환 확인·수정 → 배너 생성, 글자 대비 검사. B·C는 요청마다 빼고 싶은 요소(부정 프롬프트 태그)를 더할 수 있다 |
| C 그림체 이미지 | 장면 요청 → 영어 장면 태그 확인·수정 → 이미지 생성. B 배너 그림(글자 얹기 전)을 그대로 C 이미지로 가져올 수 있다 |
| F 굿즈 목업 | 굿즈 사진 + 디자인 → 후보 전부 생성 → 하나 고름 |
| D 굿즈 배경 | 굿즈 사진 + 장면 + 방식(R1n / Y / YR1n) → 연출 사진 |
| 상세 페이지 만들기 | 결과를 구역별로 골라 한 장으로 합성, 빈 문구는 자동 생성. 게임 화면은 등록한 레퍼런스 아트 전부 + A 스크린샷(없으면 C·B 결과에서 고름), 일러스트는 C·B 결과를 여러 장 고름 |
| 작업 대기열 | 단계별 진행 상황, 요청 목록, 단계 기록 |

- 올리는 그림 검사(27, 11/04): A 스크린샷·굿즈 사진은 긴 변 512px 이상, 레퍼런스 아트는 256px 이상, 가로:세로 3:1~3:4. 기준 밖이면 올리지 못하고 필요한 크기와 잘라야 할 길이(px)를 안내한다. 긴 변 512px는 게임 화면·굿즈 칸에서 1.2~1.8배로 늘어나지만, 실제 픽셀 확대 비교(27 `us_zoom.png`)에서 적절하다고 판단해 기준으로 정했다(27 `us_view.csv`).

- GPU 24GB에 모델을 모두 함께 올릴 수 없어(Qwen 최대 18.23GB + animagine 13.0GB, 21) 요청을 대기열에 모으고, 워커가 모델 단계별로 묶어 처리한다: 문구(Qwen) → 그림(animagine) → SDXL 빈 배경 → 마스크(BiRefNet) → Y 배경 → IC-Light → 합성(배너는 Pillow, 상세 페이지는 HTML → PNG). 단계마다 별도 프로세스에서 모델을 한 번만 올린다(21과 같은 방식).
- F 후보 합성은 GPU를 쓰지 않아 앱에서 바로 만든다. 새로 올린 굿즈 사진만 마스크 단계를 거친다.
- 그림체 설정은 12 게임별 설정과 같은 틀(그림체 태그, 빼는 태그, 장면 강조 1.3, IP-Adapter 전체 층 강도 0.3·0.5·0.8·1.0 또는 그림체 블록)로 고친다. 새 게임은 기본 설정(태그 없음, 전체 층 0.5)으로 시작하고, 예시 게임 설정을 참고해 게임에 맞게 고친다. 24에서 기본 설정은 주인공·그림체를 유지하지 못했고 게임별 설정을 써야 그림체가 유지됐다.
- 지시문·검증 규칙·모델 설정은 실험 노트북에서 채택한 코드를 그대로 옮겼다(`core/textcfg.py`, `core/children.py`, `core/mockup22.py`, `core/compose07.py`, 상세 페이지 `core/page_html.py`는 26 2번·21과 같은 코드). 21과 같은 입력으로 만든 목업은 21 결과와 픽셀 차이가 0이다.
- 결과와 기록은 `outputs/app/`에 남는다: 요청 DB `app.db`, 요청별 결과 `jobs/`, 단계별 시간 `stage_times.csv`, 워커 기록 `worker.log`.

## ▶️ 실행

- 환경: Windows, RTX 3090 24GB, Python 3.12
- 앱만 실행 (한 번 클릭): 프로젝트 폴더의 `start.bat`을 더블클릭한다. 처음 실행하면 프로젝트 폴더에 `.venv`를 만들어 `requirements-app.txt`(앱에 필요한 패키지만)와 Chromium을 설치한 뒤 앱을 켜고, 다음부터는 바로 앱을 켠다. `requirements-app.txt`가 바뀌면 다시 설치한다.
  - 미리 필요한 것: Python 3.12, git(diffusers를 GitHub 커밋에서 받음), CUDA 13(cu130)을 지원하는 NVIDIA 드라이버
  - 처음 실행은 오래 걸린다: 패키지 약 160개(torch cu130만 수 GB)를 받아 설치하고 Chromium까지 받은 뒤에 앱이 켜진다. 이 PC에서 첫 설치는 333초(약 5분 30초) 걸렸다(2026-11-04, 네트워크 속도에 따라 달라진다). 그동안 창에 설치 진행 줄이 나오고, 오류가 나면 "설치를 멈췄어요" 줄을 띄우고 멈춘다
  - 모델은 앱에서 처음 쓸 때 Hugging Face에서 받는다(수십 GB). 설치 기록은 `.venv/install_log.txt`
- 실험 노트북까지 쓰는 환경: `pip install -r requirements.txt` 뒤 `python -m playwright install chromium` (상세 페이지 합성용 브라우저)
- 앱 직접 실행: 위 환경의 프로젝트 폴더에서 `streamlit run src/app/streamlit_app.py` (워커는 앱이 자동으로 띄운다)
- 앱과 실험 노트북은 같은 GPU를 쓰므로 동시에 돌리지 않는다.
